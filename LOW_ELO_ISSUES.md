# Low-to-Mid Elo (Below 1200) AoE2 Player Issues Analysis

Based on research across the AoE2 community (Reddit, AoEZone, YouTube guides, and community forums), below is a synthesis of the most common issues hindering players below 1200 Elo. This table also outlines how our AoE2 Squire project can detect and help players correct these mistakes.

| Issue | Common | Impact | Viability | Approach | Features Needed |
| :--- | :---: | :---: | :---: | :--- | :--- |
| **Idle Town Center**<br>*(Failing to continuously produce villagers)* | 5 | 5 | 4 | Correlate villager queue events from replay with the actual `population_vils` count from the vision UI. If `population_vils` is stagnant and no queue event was recently issued, the TC is idle. | Parsing the on-screen **global unit/tech queue** would definitively confirm if a villager is currently in production. |
| **Idle Villagers**<br>*(Leaving villagers inactive)* | 5 | 4 | 5 | Monitor the `idle_vils` counter directly using our DXGI vision pipeline's yellow icon detection and digit OCR. | Track total duration and count of idle villagers to calculate economic opportunity cost. |
| **Floating Resources**<br>*(Stockpiling unspent resources)* | 5 | 4 | 5 | Monitor resource banks over time using the DXGI vision pipeline (OCR on the UI). Flag sustained periods where resources exceed healthy thresholds. | Dynamic thresholds based on current Age and active strategy (e.g., floating food before Castle Age is expected). |
| **Getting "Housed"**<br>*(Hitting the population cap)* | 4 | 3 | 5 | Directly detect the yellow "housed" UI overlay state using our vision pipeline (`detect_housed_overlay`). | Track total duration of the housed state to calculate production time lost. |
| **Poor Build Order Execution**<br>*(Inefficient resource allocation or delayed Age up)* | 4 | 3 | 2 | Compare player's Age-up queue timings, building queue sequences, and tech queues against known standard benchmarks. | Database of standard build orders. Detecting the **current age** UI element would provide exact age-up completion timings. |
| **Over-Committing / Ignoring Counters**<br>*(Sticking to one unit type when countered)* | 4 | 3 | 2 | Parse military unit queue events for both players. Analyze opponent's queued composition and flag if the player is continuously queuing countered units. | A unit-counter matrix, and a **Civ tech tree data file** to verify what counter units the player's civilization can actually train. |
| **Lack of Production Buildings**<br>*(Having strong economy but too few military buildings)* | 3 | 4 | 2 | Approximate building counts using queued building events from the replay. Flag if resources are floating while queued production count is low. | Detecting the **bottom selection panel** could ground-truth the active building count when a player uses "select all" hotkeys. |
| **Delayed Economic Upgrades**<br>*(Forgetting Double-Bit Axe, Horse Collar, Wheelbarrow)* | 4 | 2 | 3 | Track technology queue events from the replay parser. Flag if crucial economic upgrades are queued significantly later than the target window. | Detecting **current age** to avoid penalizing players before a tech is available, and a **Civ tech tree data file** to confirm the tech exists for that civ. |
| **Poor Scouting / Map Awareness**<br>*(Not finding resources or enemy base)* | 5 | 3 | 1 | Very difficult to infer from replay parsing alone without full spatial awareness. | Capturing the **Minimap** (bottom right) could allow us to calculate the percentage of explored map over time, and flag "dark" areas. |
| **Poor Multi-tasking / Tunnel Vision**<br>*(Neglecting eco while fighting)* | 5 | 4 | 1 | Detect periods of high APM or combat (if parsing combat events) correlating with sudden spikes in floating resources or stagnant `population_vils`. | Advanced correlation logic linking combat proximity/intensity to macro-level economic drops. |

## Key Takeaways for AoE2 Squire Value:
1. **The Basics are Paramount:** High-impact features focus on fundamental macro mechanics (Idle TC, Floating Resources, Getting Housed). 
2. **Hybrid Architecture Utility:** The hybrid approach (Replay Parsing + Vision OCR) supports comprehensive analysis. Replay parsing provides exact events (training, tech, buildings), while the vision pipeline supplies the economic context (current pop, floating resources) necessary to evaluate event execution and stalling.
3. **High-Value Vision Expansions:** To expand the tool's capabilities, additions to the DXGI capture pipeline include:
   - **Game Timer (F11 Clock):** Capturing the top-screen clock enables absolute synchronization between vision data and replay parser data, removing synchronization heuristics.
   - **Global Queue:** Resolves the "Idle TC" detection problem by verifying when a villager is actively training.
   - **Minimap:** Enables features for evaluating scouting and map control.
4. **Data Infrastructure Needs:** To provide accurate contextual coaching, a comprehensive **Civilization Tech Tree Data File** is required. This ensures the system does not penalize a player for failing to train a specific counter unit or research a technology that their civilization does not possess.
