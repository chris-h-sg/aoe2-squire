# Game data: sources and how to update them

| File | What | Source | Used by |
|---|---|---|---|
| `game_data.csv` | Units, buildings and technologies (age-ups and unit upgrades included) by ID: kind, ID, English name, food/wood/gold/stone cost | Generated by `tools/update_game_data.py`: IDs and costs from [SiegeEngineers/aoe2techtree](https://github.com/SiegeEngineers/aoe2techtree) (`data/data.json`, the data behind aoe2techtree.net), names from [SiegeEngineers/halfon](https://github.com/SiegeEngineers/halfon) (`data/units_buildings_techs.de.json`, `localised_name`) | `src/game_data.rs` (embedded in the binary) |
| `civilizations.csv`, `maps.csv` | Civilization and map names by ID | Parsed from `aoc_reference_data.de.json`, a copy of [`data/datasets/100.json` in SiegeEngineers/aoc-reference-data](https://raw.githubusercontent.com/SiegeEngineers/aoc-reference-data/master/data/datasets/100.json) | `src/replay.rs` |

Both upstream projects are MIT-licensed.

## `game_data.csv`

**Current version: DE Update 188329** (aoe2techtree
`e56728e76b7d08301fba7b18d5f16bc8554c109a`, halfon `7f96c37fc5f63c7141ec7d88e91c627beb375b28`,
both 2026-10-27). The same commits are the defaults in `tools/update_game_data.py`.

The code works on IDs only: replay commands carry unit, building and technology IDs, and
age-ups are recognised by technology ID (101 Feudal, 102 Castle, 103 Imperial;
`src/game_data.rs`). Names are only for display. Costs are base costs: civilization bonuses
and discounts are not applied. Unit and building IDs share one namespace in the game,
technologies have their own; unit upgrades (Crossbowman, Pikeman, ...) are technologies.

Why two sources: aoe2techtree has clean, current costs for everything a player can build,
but its names need reverse-engineered string lookups. Halfon has every object of the game
with a plain English name, but its raw costs have quirks (0 for some upgraded units and
gates). Both are maintained by SiegeEngineers and updated on the day of each game update.

### Updating after a game update

1. Find the commits that implement the game update. Both projects title them
   "Implement DE Update <build>":
   ```bash
   gh api "repos/SiegeEngineers/aoe2techtree/commits?per_page=5" --jq '.[] | "\(.sha) \(.commit.message | split("\n")[0])"'
   gh api "repos/SiegeEngineers/halfon/commits?path=data/units_buildings_techs.de.json&per_page=5" --jq '.[] | "\(.sha) \(.commit.message | split("\n")[0])"'
   ```
   Use the commits for the same build. A replay's build is printed by
   `cargo run -- --parse-replay <replay>` ("Build: ...").
2. Set `TECHTREE_COMMIT` and `HALFON_COMMIT` in `tools/update_game_data.py` to the full SHAs
   (or pass `--techtree` / `--halfon` to try them first), then run:
   ```bash
   python tools/update_game_data.py
   ```
   It downloads both files at those commits (nothing else is fetched; no dependencies beyond
   Python 3), merges them and rewrites `data/game_data.csv`. It stops with an error if an
   aoe2techtree entry has no name in Halfon or an ID appears twice with different values.
3. Review `git diff data/game_data.csv`: every changed cost should match the game update's
   patch notes. New units and techs appear as added rows.
4. Update "Current version" above.
5. Run `cargo test`. The `game_data` unit tests check known entries (Militia, the age-ups,
   Town Center, Castle). Snapshot and sanity report tests show what the new costs change in
   the recorded games; review each difference before regenerating with
   `UPDATE_SNAPSHOTS=1` (see `test_bench/README.md`).
6. Commit the script change, `data/game_data.csv` and this file together.

### Unknown IDs

When a replay command refers to an ID that is not in `game_data.csv`, its name shows as
"Unknown unit 1234" (or building / tech), its cost as 0, and the replay parse prints
`Unknown IDs (not in data/game_data.csv, no name or cost): ...` (also at the top of the
sanity report output). If that happens for a current replay, the ID is missing from
aoe2techtree (it lists only what players can build); check Halfon or the game data for it
before adding a source.

### Display name overrides

`NAME_OVERRIDES` in the script replaces a few Halfon names that differ from what the game
shows (Halfon calls unit 83 "Villager (Male)"). Keep it short, with a reason per entry.
